# ViFinQA RAG Module - Teammate Guide

## What is this?

This folder (`rag_module/`) contains everything your teammate needs to run a
Hybrid Search RAG pipeline over Vietnamese financial statements on Kaggle.
It combines Dense retrieval (Qdrant vector DB) and Sparse retrieval (BM25)
using Reciprocal Rank Fusion (RRF) to merge results.

---

## Folder Structure

```
rag_module/
├── __init__.py           # Package entry -- exports run_hybrid_search
├── data_pipeline.py      # Full ETL + Indexing pipeline (run this first to build the index)
├── search_engine.py      # Hybrid search engine (import this in your notebook)
├── eval_retrieval.py     # Batch evaluation against questions.jsonl
├── code_stock.csv        # Ticker to company name mapping
├── requirements.txt      # All Python dependencies
├── qdrant_local_db/      # Qdrant vector index (generated by data_pipeline.py)
├── bm25_index.pkl        # BM25 sparse index  (generated by data_pipeline.py)
├── HUMAN_README.md       # This file
└── AI_CONTEXT.md         # Architecture notes for AI assistants
```

Note: `qdrant_local_db/` and `bm25_index.pkl` are generated files.
You must run `data_pipeline.py` locally first, then upload the entire
`rag_module/` folder (including the generated index files) to Kaggle.

---

## Step 1 - Build the Index Locally

If `qdrant_local_db/` and `bm25_index.pkl` do not exist yet, run this from
the project root (the directory containing `financial_statements/`):

```bash
pip install -r rag_module/requirements.txt

# ETL only (default) -- extract HTML tables → CSV files
python rag_module/data_pipeline.py

# Full run: ETL + Indexing -- takes roughly 30-60 minutes for 1973 files
python rag_module/data_pipeline.py --run-indexing

# If processed_data/ CSVs already exist from a previous run, skip ETL and only run indexing:
python rag_module/data_pipeline.py --skip-etl --run-indexing
```

> **Note:** By default, only Phase 1 (ETL) runs. You must pass `--run-indexing`
> to also build the Qdrant vector DB and BM25 index (Phase 2).

After running with `--run-indexing` you will have:
- `rag_module/qdrant_local_db/` -- Qdrant vector index (roughly 1 GB)
- `rag_module/bm25_index.pkl`   -- BM25 sparse index (roughly 50 MB)

---

## Step 2 - Upload to Kaggle

1. Zip the entire `rag_module/` folder, including `qdrant_local_db/` and `bm25_index.pkl`.
2. Go to kaggle.com/datasets and click "New Dataset".
3. Upload the zip and give it a name, for example `vifinqa-rag-module`.
4. Set visibility to Private (or Public if you prefer).

---

## Step 3 - Configure Paths for Kaggle

Before uploading, open `rag_module/search_engine.py` and uncomment the Kaggle
path block near the top of the file, setting your dataset name:

```python
# In rag_module/search_engine.py, find the CONFIGURATION section and change:
_KAGGLE_ROOT   = Path("/kaggle/input/vifinqa-rag-module/rag_module")
QDRANT_DB_PATH = _KAGGLE_ROOT / "qdrant_local_db"
BM25_PATH      = _KAGGLE_ROOT / "bm25_index.pkl"
CODE_STOCK_CSV = _KAGGLE_ROOT / "code_stock.csv"
```

The same override comments exist in `eval_retrieval.py` if you use that too.

---

## Step 4 - Use in a Kaggle Notebook

Attach your dataset in the notebook sidebar, then run:

```python
import sys
sys.path.append("/kaggle/input/vifinqa-rag-module")

# Install dependencies (run this cell once)
# !pip install -r /kaggle/input/vifinqa-rag-module/rag_module/requirements.txt

from rag_module.search_engine import run_hybrid_search, search_by_table_name, search_by_column_name

# --- Hybrid Search ---
# First call loads all resources (roughly 30 seconds for model download)
results = run_hybrid_search("Loi nhuan sau thue cua FPT nam 2023", top_k=5)

for r in results:
    print(r["Ten_Bang"], "|", r["Ma_Doanh_Nghiep"], r["Nam_Tai_Chinh"],
          "| RRF:", r["rrf_score"])
```

You can also pass explicit overrides if auto-parsing fails:

```python
results = run_hybrid_search(
    query       = "Doanh thu thuan",
    ticker      = "VCB",
    year        = "2022",
    report_type = "consolidated",
    top_k       = 10,
)
```

## Targeted Search Helpers

If you know exactly what table or column you are looking for, you can use the targeted search helpers. These use exact/fuzzy metadata matching instead of embedding search:

```python
# Find tables by their name (e.g., "bảng cân đối kế toán")
table_results = search_by_table_name("FPT", "bảng cân đối kế toán", year="2022")

# Find tables that contain a specific column (e.g., "Số cuối năm")
col_results = search_by_column_name("FPT", "Số cuối năm")
```

---

## What run_hybrid_search Returns

A list of dicts sorted by `rrf_score` (highest first). Each dict contains:

| Key                | Description                              |
|--------------------|------------------------------------------|
| `rrf_score`        | Fused relevance score (higher is better) |
| `dense_rank`       | Rank from Qdrant dense search            |
| `sparse_rank`      | Rank from BM25 sparse search             |
| `csv_path`         | Absolute path to the source CSV          |
| `Ten_Bang`         | Table name                               |
| `Ma_Doanh_Nghiep`  | Ticker code                              |
| `Ten_Doanh_Nghiep` | Company name                             |
| `Nam_Tai_Chinh`    | Financial year                           |
| `Loai_Bao_Cao`     | Report type (separate / consolidated)    |
| `Don_Vi_Tinh`      | Currency unit                            |
| `col_names`        | Comma-separated data column headers      |

## Notes on Kaggle Read-Only Filesystem

Kaggle input directories are read-only. Qdrant automatically detects this and
opens the database in read-only mode, so no special handling is needed.
